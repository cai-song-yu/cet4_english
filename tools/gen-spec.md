# 文章生成规范（gen-spec · 生成第 11–90 篇必须遵守）

> 目标：按 `course/roadmap.md` 的难度路线，为 `assets/js/articles.js` 追加高质量文章数据。
> **唯一交付物**：`build/parts/NNN.json`（单篇一个 JSON 文件）。不改 `articles.js`、`app.js`、`index.html`、`reader.css`（入库由 `tools/build.js` 完成）。
> **验收**：`node tools/validate.js build/parts/NNN.json` 退出码为 0（零错误）。警告也请尽量清零。
> 风格参照：`assets/js/articles.js` 里第 2 篇（第 188–366 行）是标准范本，动笔前先读一遍。

## 0. 工作流程

1. 读 `course/topics.md` 里自己负责篇目的行（标题、中文标题、题材、梗概）——**不得另起题目**。
2. 读 `course/style-guide.md` 与本文件。
3. 需要复现词时运行 `node tools/ledger.js <起始篇号>`（例如生成第 11 篇跑 `node tools/ledger.js 11`），拿到"此前已教核心词 + 短语"清单。
4. 写 `build/parts/NNN.json` → 跑校验器 → 按报错修 → 直到 `✓`。
5. 一篇一文件；一次任务负责多篇时，每篇单独一个文件（`011.json`、`012.json` …）。

## 1. JSON 书写约定

- 文件是**一个 JSON 对象**（不是数组）；UTF-8 无 BOM。
- 英文文本里所有撇号、引号一律用**弯引号** `’ “ ”`（如 `It’s`、`“Any questions?”`），**不要用直引号** `'"`，避免转义出错。
- 中文用全角标点；中文里不要夹英文单词（译文、释义都不行，专有名词也要译成中文）。
- 每个字符串都是单行（JSON 里不能有真换行）。

## 3. 正文 `body[]` 与标注

- **纯英文**，不混任何中文（`data-cn` 属性里的中文不算正文文本，前端不显示为正文）。
- 段落数随篇幅 6–10 段，每段是一个完整语义段，长度均衡。
- 标注只有这 6 种，**不得嵌套**（span 里不能再有 span）：

| 类 | 用途 | 语法 |
|---|---|---|
| `w-cet4` | 本篇新授核心词（必在 `vocabulary` 里） | `<span class="w-cet4" data-cn="中文释义">manage</span>` |
| `w-phrase` | 本篇新授短语（必在 `phrases` 里） | `<span class="w-phrase" data-cn="中文意思">give up</span>` |
| `w-writing` | 写作表达（与某条 `writings.expr` 对应） | `<span class="w-writing" data-cn="在我看来……">In my opinion</span>` |
| `w-sentence` | 长难句（整句包起来，`sentences[]` 里要解析它） | `<span class="w-sentence">…完整句子…</span>` |
| `w-synonym` | 同义替换 / 辨析 | `<span class="w-synonym" data-cn="＝ important 的替换词">significant</span>` |
| `w-rev` | **复现旧词**（不加 data-cn、不着色） | `<span class="w-rev">afford</span>` |

- `w-cet4 / w-phrase / w-writing / w-synonym` **必须带 `data-cn`**；`w-sentence / w-rev` **不带**。
- 标注数量按下表（校验器硬性区间），宁少勿多，不许满篇标注：

| 阶段 | 正文词数 | 词表 | 新词密度 | w-cet4 | w-phrase | w-writing | w-sentence | w-synonym | w-rev |
|---|---|---|---|---|---|---|---|---|---|
| 二 11–20 | 250–325 | 10–14 | 3–4.5% | 9–12 | 3–5 | 2–3 | 1–2 | 0–1 | 4–8 |
| 三 21–30 | 300–405 | 12–18 | 4–6% | 12–16 | 4–5 | 2–3 | 2–3 | 1–2 | 5–9 |
| 四 31–45 | 400–505 | 15–20 | 5–7% | 13–18 | 4–6 | 2–4 | 3–5 | 1–3 | 5–10 |
| 五 46–60 | 450–555 | 15–22 | 6–8% | 14–20 | 5–6 | 3–4 | 4–6 | 2–3 | 8–14 |
| 六 61–75 | 500–605 | 18–25 | 6–8% | 14–22 | 5–7 | 3–4 | 4–6 | 2–4 | 10–16 |
| 七 76–90 | 550–705 | 15–20 | 5–7% | 14–20 | 5–7 | 3–4 | 4–6 | 2–4 | 10–16 |

（词数沿阶段递进，例如阶段二：第 11 篇约 260 词 → 第 20 篇约 315 词；同阶段内逐篇递增。）

## 4. `translation[]` 逐段译文

- 与 `body[]` **严格等长、逐段对应**。
- 自然的现代汉语，不逐词硬译；可保留原文的短句节奏。
- **忠实于原文**：不添加原文没有的情节、原因或心理活动（原文说"我说自己很忙"才译这句）。
- **不含任何英文单词**（含缩写）；人名、地名译成中文。

## 5. `vocabulary[]` 核心词表

- 条数见上表；字段 `w / ph / pos / cn / col / ex`。
- `w`：单词原形（不带词性后缀）；正文里可以用屈折形式（`manage → managed`），校验器按词族识别。
- `ph`：音标，必以 `/` 开头，如 `/ˈmænɪdʒ/`。
- `pos`：词性，`n. / v. / vt. / vi. / adj. / adv. / conj. / prep.`，多词性用 `n./v.`。
- `cn`：中文释义。
- `col`：常见搭配，**每条搭配后用「—」接中文意思**，两条用「；」分隔，如 `manage to do sth. — 设法做成某事；manage a team — 管理一个团队`。
- `ex`：纯英文例句。
- **约束**：正文里 `w-cet4` 标注的词必须都在词表里；词表里的词必须在正文出现。

## 6. `phrases[]` 高频短语与固定搭配

- 8–14 条，字段 `en / cn / ex`；`cn` 必含中文意思，动词搭配优先（`give up — 放弃`）。
- `en` 可用记法：`be afraid of doing sth.`、`throw … away`、`put up one’s hand`。
- **约束**：正文 `w-phrase` 标注的短语必须在表里。

## 7. `writings[]` 写作表达

- 固定 2 条；字段 `expr / cn / meaning / context / alts / register / example`。
- `alts` 2–3 条，每条 `{ t: 替换表达, n: 备注（可为空串） }`。
- `expr` 要和正文里 `w-writing` 标注的表达一致。

## 8. `sentences[]` 长难句解析

- 条数见上表（阶段二 2–3 条，之后递增）；字段 `text / points`。
- `text` **逐字取自正文**（不带标注标签），`points` 3–5 条中文讲解，覆盖：主干、语法点、为什么值得学、注意点、常见变体。
- 每个 `text` 对应正文里一个 `w-sentence` 标注（数量要对得上）。

## 9. `questions[]` 阅读理解训练

- 固定 5 题；字段 `en / cn / ans / ansCn`（题干英文 + 中文 + 参考答案英文 + 中文）。
- 题型分布（按阶段，roadmap §4）：
  - 11–20：事实细节 2、简单推断 1、段落作用 1、指代判断 1
  - 21–30：细节 2、主旨 1、同义替换识别 1、词义猜测 1
  - 31–45：细节 2、推断 1、论证关系 1、态度 / 写作目的 1
  - 46–60：推断 2、作者观点 1、篇章结构 1、"作者为什么提到 X" 1
  - 61–75：全题型（主旨 / 细节 / 推断 / 词义 / 态度各 1）
  - 76–90：隐含意义 2、作者立场 1、结构 1、批判性问题（评价论证或假设）1
- **答案唯一**，必须能从原文直接找到或唯一推出；不要出"你觉得呢"这种开放题。

## 10. 输出任务

- `writingTask.en` 词数区间必须与阶段一致：二 60–80、三 80–100、四 100–120、五 / 六 120–150、七 150–180（写作格式 `Write 60–80 words about …`）。
- `hints` 2–4 条英文句架，`hintCn` 中文说明，`req` 要求用到本篇词 / 搭配（点名具体词）。
- `speakingTask`：阶段二 45 秒 + 一个理由；三 1 分钟观点 + 理由 + 例子；四 1 分钟结构化（观点→原因→例子）；五 1.5–2 分钟 + 反驳；六 2 分钟 + 高级表达；七 2 分钟 + 让步与反驳。
- `speakingTask.points` 2–4 条要点，`pointCn` 中文提示，`skeleton` 英文答题骨架。

## 11. `focus[]` 本篇学习重点

- 常规篇 5 条；**节点篇（20/30/45/60/75/90）7 条**。
- 必含两条：
  - `<b>新授核心词 N 个</b>：<span class='en'>词1, 词2, …</span> —— 一句话讲这批词怎么记（词形、可数与否、固定搭配等）`（N 与词表条数一致）
  - `<b>本篇复现的旧词</b>：第 X 篇的 <span class='en'>词</span>（语境）…`（点名复现了哪些旧词与来自哪篇）
- 其余 3 条写：句型 / 搭配 / 全文逻辑线 / 题型提醒等（用 `<b>` 小标题开头）。
- 节点篇多出的 2 条写 `⭐ 本阶段复盘`：词汇抽查（点 10 个旧词让读者盖住释义自测）、下阶段难度确认。

## 12. `standard` 推荐完成度

- `time`：`约 N 分钟`，区间见下表；`bar`：一句话总纲（含题数与词数等真实数字）。
- `items` 固定 7 条，`k` 顺序必须是 `词汇 / 搭配 / 长难句 / 阅读题 / 写作 / 口语 / 复现`，`lvl` 顺序 `必达 / 建议 / 必达 / 必达 / 必达 / 建议 / 加分`。
- **条目里的数字必须来自真实数据**（校验器会核对）：
  - 词汇条含词表条数（如「遮住中文能说出 12 个核心词中的 9 个」）
  - 搭配条含短语条数
  - 阅读题条含题数（5 题至少对 4 题）
  - 复现条含正文 `w-rev` 灰点实际数
- 建议用时区间：二 25–35 / 三 30–40 / 四 35–45 / 五 45–55 / 六 50–65 / 七 55–70 分钟。

## 13. `meta` 与元信息

- 4 项：`篇幅（约 N 词，N 取实测词数的 5 倍数）/ 新词密度（约 X%，落在阶段区间）/ 长难句（N 处，= sentences 条数）/ 阅读题（5 题）`。
- `slug` = 三位篇号 + 标题小写、非字母数字转连字符（校验器会核对，照抄 topics.md 标题算即可）。
- `stage` / `stageRange` 见骨架；`cover` = `assets/covers/NNN.jpg`；`coverCredit` 暂写 `Photo: 待补 / Pexels`。

## 14. 复现机制（本课程最重要的机制）

1. 新授核心词尽量在**之后 5 篇内复现**：写新篇目时，先从 `node tools/ledger.js` 的词池里挑 5–8 个词织进正文，用 `w-rev` 灰点标出（**不带 data-cn**）。
2. `w-rev` 标的必须是**此前文章教过的词 / 短语**（校验器会核对）；本篇新授词一律用 `w-cet4`。
3. 一篇里同一个词只标一次 `w-rev`；`w-rev` 不要和 `w-cet4` 混用同一个词。
4. `focus` 的「本篇复现的旧词」里点名这些词与来源篇目。

## 15. 内容质量红线

- **真实可读**：说明文里的数据、结论要符合常识（不必精确引用来源，但不能编造反常识结论）；记叙文情节前后一致（时间、人物、数字）。
- **不写真实品牌 / 公司 / 人名**：用 `a coffee shop`、`a phone maker` 代替；地名用通用说法。
- 不涉及政治、宗教、色情、暴力、争议性群体评价；健康类话题不下"包治"式结论。
- 语言难度要符合阶段：句子长度、抽象度、从句嵌套随阶段递进，不要用超纲难词堆砌难度。
- 每篇要有**一个清楚的立意或收获**，结尾自然收束，不喊口号。

## 16. 自检清单（交稿前逐条过）

- [ ] 正文通读：纯英文、无标注嵌套、标注密度合适
- [ ] 译文逐段对得上，读起来像人话
- [ ] 阅读题答案能从原文唯一推出
- [ ] `standard` 里的数字与实际数据一致
- [ ] `focus` 点名了复现的旧词
