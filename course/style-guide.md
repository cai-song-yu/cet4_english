# 文章输出规范（v3.2 · 所有文章必须遵守）

## 0. 交付方式：前端页面优先

- **主交付物是前端阅读器**：双击根目录 `index.html` 打开（无需服务器），或访问 `http://127.0.0.1:8777`（若本地服务器在运行）。
- **缓存刷新**：`index.html` 中所有 css/js 引用带 `?v=X.X` 版本号；**每次修改前端文件或新增文章后，必须把版本号 +0.1**，防止浏览器用旧缓存（用户如仍看到旧界面，按 Ctrl+F5 强制刷新）。
- **文章内容 = 数据**：每篇文章是 `assets/js/articles.js` 中的一个对象，追加数据即自动上站；
  **前端代码（index.html / reader.css / app.js）只写一次，任何情况下都不要为单篇文章重复改代码。**
- 新增一篇文章的步骤：
  1. 在 `assets/js/articles.js` 的 `window.ARTICLES` 数组末尾追加一个对象（字段参照第 1 篇）；
  2. 下载主题封面图到 `assets/covers/00N.jpg`（真实摄影作品，Wikimedia Commons 等 CC 授权来源，禁止二次元图片）；
  3. 同步更新 `articles/README.md` 索引和 `course/progress.md` 日志。
- 数据字段：`id / slug / title / titleCn / stage / stageRange / meta[] / cover / coverCredit / body[]（纯英文段落）/ translation[]（逐段中文译文，与 body 等长）/ vocabulary[] / phrases[] / writings[] / sentences[] / questions[] / writingTask / speakingTask / focus[] / standard（推荐完成度达标线）`

## 1. 文章正文：纯净原则（对应 `body` 字段）

- **正文必须是纯英文**，不混入任何中文（包括 "— 中文意思"、括号注释、破折号说明）。
- 文中标注只保留**颜色 + 加粗**，所有解释一律放到正文下方的表格和解析中。
- 例（❌ 错误）：`<b>on the way</b> — 在路上`
- 例（✅ 正确）：`<span style="color:#2E7D32"><b>on the way</b></span>`
- 正文写完后通读一遍：只看正文，应该就是一篇干净的英文短文。

### 1b. 中文译文（对应 `translation` 字段）

- **译文与 `body[]` 严格等长、逐段一一对应**：正文第 N 段对应 `translation[N-1]`。前端按位置成对渲染，缺一段、多一段都会被校验脚本拦下。
- 译文渲染为独立的 `<p class="tr">`，紧跟在该段英文之后，**永远不写进 `body[]`** —— 「正文纯英文」这条原则不因为有了译文而放宽。
- 译文默认**隐藏**，由读者点正文上方的 🈶 按钮或按 `L` 自行显隐（状态跨篇记忆）。因此译文不是「注释」，而是**对照材料**：先读英文，卡住了再看。
- 译文写自然的现代汉语，**不逐词硬译**；原文的标点节奏（短句、并列、破折）可以保留，但中文里不要出现英文单词或短语。
- 校验点：段数相等、译文不含 ≥4 字母的英文单词、`body[]` 全篇零中文。

### 1c. 推荐完成度（对应 `standard` 字段）

每篇必须给一条**可核对的达标线**，回答「学到什么程度才行」：

- `time`：建议用时（分钟，随篇幅与难度 25→35 递增）。
- `bar`：一句话总纲，读者扫一眼就知道验收口径。
- `items[]`：**固定 7 条**，分三档 —— `必达` ×4（词汇 / 长难句 / 阅读题 / 写作）、`建议` ×2（搭配 / 口语）、`加分` ×1（第 1 篇为「结构」，之后各篇为「复现」）。
- 条目里的**所有数字必须来自实际数据**：词表条数、短语条数、阅读题数、写作词数、正文 `.w-rev` 灰点数 —— 写之前先数，不许写「大约」「若干」这类虚数。
- 前端把 7 条渲染成可勾选清单并算出完成度百分比，勾选状态存 `reader-std` 跨页记忆。

## 2. 排版整洁

- 段落之间空一行，正文不出现表格、列表、中英混排。
- 文章元信息（篇目、阶段、图例）放在正文前的引用块 `>` 中，与正文有分隔线隔开。
- 正文只保留 `**A Better Morning**` 标题和自然段。
- 下方各板块用统一的 `## 一～九` 标题 + 分隔线，层级清晰。

## 3. 颜色标注体系（不用文字标签）

用 HTML `<span>` 上色，**不使用** [CET4:] 这类文字标签。

| 颜色 | 含义 | 代码 |
|---|---|---|
| 🔵 蓝色 | CET-4 核心/高频词汇 | `<span style="color:#1565C0">...</span>` |
| 🟢 绿色 | 高频短语 / 固定搭配 | `<span style="color:#2E7D32">...</span>` |
| 🟠 橙色 | 值得模仿的写作表达 | `<span style="color:#E65100">...</span>` |
| 🔴 红色 | 长难句 | `<span style="color:#C62828">...</span>` |
| 🟣 紫色 | 同义替换 / 词汇辨析 | `<span style="color:#6A1B9A">...</span>` |

- 每篇文章开头的引用块中放一次**颜色图例**。
- 标注词用 `<b>` 加粗。
- 只标注真正值得学的内容，不标满（数量控制见 roadmap 第 9 节）。

## 4. 音标与词性（只给单词，且只在词汇表中）

- **只标注"单词"**；短语、写作表达不标音标。
- **每个单词必须标注词性**（n. / v. / vt. / vi. / adj. / adv. / conj. / prep. 等），多词性用 `n./v.` 形式。
- **文章正文中不出现音标和词性。**
- **不单独开音标列**——音标和词性紧跟单词写在同一格：
  - `| **afford** /əˈfɔːd/ vt. | 负担得起 | ... |`
- 词汇表字段：`w / ph（音标）/ pos（词性）/ cn / col（搭配含意思）/ ex（例句）`。

## 5. 固定搭配必须给中文意思

- 所有短语、搭配**必须附中文释义**（放在短语表里，不放正文），否则不列出。
- **动词搭配重点给意思**，例如：`give up — 放弃`、`pay attention to — 注意、专心于`、`make a change — 做出改变`。
- 搭配表格式：`搭配 | 中文意思 | 简单例句`
- 特别重视**动词 + 名词 / 动词 + 介词**类高频搭配。

## 6. 其余结构

九段式（前端自动渲染为 8 个板块，写作+口语任务合并为「输出任务」）：
正文 → 核心词汇 → 高频短语与固定搭配 → 写作表达 → 重点句子解析 → 阅读理解训练 → 输出任务（写作 + 口语）→ 本篇学习重点。

## 7. 前端交互（一次性功能，无需每篇配置）

- 目录栏可收起（☰ 目录），正文字号 A− / A+ 可调并记忆
- 页面顶部阅读进度条，右下角回到顶部
- 阅读题「显示参考答案」按钮：默认隐藏，点击才显示（题目数据字段：`ans` / `ansCn`）
- 键盘 ← → 翻页
